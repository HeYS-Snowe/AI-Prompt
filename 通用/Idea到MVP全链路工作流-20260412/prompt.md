# Idea 到 MVP 全链路工作流

> 适用场景：学生独立开发者，将想法转化为可上线的产品
> 核心原则：先跑通核心流程、Mock 数据先行、小步快跑
> 参考来源：Addy Osmani、火山引擎社区、Vibe Vibe 教程、独立开发者社区

---

## 一、全链路路线图

```
Idea → 验证 → 设计 → 前端 → 后端 → 集成 → 部署 → 迭代
  ↓      ↓      ↓      ↓      ↓      ↓      ↓      ↓
 1天    1天    2天    3天    5天    2天    1天    持续
```

---

## 二、各阶段详解

### 阶段 1：Idea 验证（1 天）

```
回答三个问题：
1. 解决什么问题？（痛点）
2. 给谁用？（用户画像）
3. 怎么解决？（核心功能）

验证方法：
- 搜索是否已有类似产品
- 找 3-5 个潜在用户聊需求
- 确认核心功能是否足够简单到能快速实现

产出：一页纸的需求描述（Who/What/Why）
```

### 阶段 2：需求定义（1 天）

```
核心功能清单（最多 5 个）：
1. [必须有的功能]
2. [必须有的功能]
3. [必须有的功能]

不要做的功能（明确排除）：
- [暂不实现]
- [暂不实现]

数据模型草稿：
- User: { id, email, name, created_at }
- [核心实体]: { ... }

产出：功能清单 + 数据模型定义
```

### 阶段 3：技术栈选择（半天）

```
决策框架：

前端：
- 简单展示页 → HTML + Tailwind CSS
- 需要交互 → React/Next.js + Tailwind CSS
- 移动端优先 → Flutter / React Native

后端：
- 无后端经验 → Supabase（BaaS）
- Python 熟悉 → FastAPI + SQLite/PostgreSQL
- JS/TS 熟悉 → NestJS/Express + PostgreSQL

部署：
- 前端 → Vercel（免费）
- 后端 → Railway / Render（免费额度）
- 数据库 → Supabase / Neon（免费层）

原则：选你熟悉的，不要追求最优解
```

### 阶段 4：前端开发（3 天）

```
Day 1：核心页面骨架
├── 搭建项目结构
├── 用 Mock Data 构建核心页面
└── 实现基本导航

Day 2：交互与状态
├── 表单验证
├── Loading / Error / Empty 三种状态
└── 响应式适配

Day 3：视觉优化
├── 应用设计系统（参考 .prompt/设计/ 中的规范）
├── 动效打磨
└── Mock Data 确认（为后端准备数据契约）

产出：可交互的前端 + Mock Data + TypeScript 接口定义
```

### 阶段 5：后端开发（5 天）

```
Day 1：项目搭建 + 数据库
├── 初始化项目（参考 .prompt/后端/项目结构规范）
├── 定义 ORM 模型（基于前端的数据契约）
└── 生成迁移脚本 + seed 数据

Day 2：认证系统
├── 注册 / 登录 / 登出
├── JWT Token 管理
└── 中间件

Day 3-4：核心 API
├── CRUD 端点（基于前端需求）
├── 输入验证 + 错误处理
└── 分页 + 筛选

Day 5：文档 + 测试
├── OpenAPI/Swagger 文档
├── 关键路径单元测试
└── API 手动测试

产出：可调用的 API + 文档 + 测试
```

### 阶段 6：前后端集成（2 天）

```
Day 1：
├── 替换 Mock Data 为 API 调用
├── 认证流程打通
└── 统一错误处理

Day 2：
├── 端到端测试
├── Bug 修复
└── 性能检查

产出：完整可用的应用
```

### 阶段 7：部署上线（1 天）

```
1. 前端部署到 Vercel
2. 后端部署到 Railway / Render
3. 数据库迁移
4. 环境变量配置
5. 域名绑定
6. 上线检查清单（参考 .prompt/通用/部署与维护指南）
```

### 阶段 8：持续迭代

```
收集反馈 → 优先级排序 → 新一轮开发
├── 用户反馈
├── 数据分析（访问量、转化率）
├── Bug 修复
└── 新功能开发
```

## 三、核心原则

### 1. MVP 思维

```
最小可行产品 = 最少功能 + 可以运行
- 先做核心流程，其他以后再说
- 不要追求完美，追求可用
- 上线比完美更重要
```

### 2. Mock 数据先行

```
前端先跑通 → 定义数据契约 → 后端实现契约
- Mock Data 就是 API 的规格说明书
- TypeScript 接口定义就是数据契约
- 前后端并行开发的桥梁
```

### 3. 小步快跑

```
每次只做一件事：
- 一个功能 → 测试 → commit → 下一个
- 不要一次性改多个功能
- 每个阶段有明确的成功标准
```

### 4. AI 辅助的正确姿势

```
AI 擅长：代码生成、重复任务、重构、测试、审查
你应主导：架构决策、业务逻辑、安全审查、复杂 Bug

工作模式：
- 你写 Prompt → AI 生成代码 → 你审查 → 运行测试 → commit
- 不要盲目接受 AI 输出
- 每次只让 AI 做一件事
```

## 四、常用 Prompt 模板

### 需求分析 Prompt

```
我有一个产品想法：
[描述你的 idea]

请帮我分析：
1. 这个产品的核心价值是什么？
2. 最小可行产品需要哪些功能？（最多 5 个）
3. 技术栈建议是什么？
4. 有什么潜在风险？
5. 预估开发时间？

不要写代码，只做分析。
```

### 数据模型设计 Prompt

```
基于以下功能需求，设计数据模型：

功能：
[列出核心功能]

请输出：
1. 实体列表（每个实体的字段和类型）
2. 实体之间的关系
3. JSON Schema 定义
4. 需要的索引

不要写代码，只输出设计。
```

### 全栈项目初始化 Prompt

```
我要开发一个 [项目描述] 的全栈项目。

技术栈：
- 前端：Next.js + Tailwind CSS + TypeScript
- 后端：FastAPI + SQLAlchemy + PostgreSQL
- 部署：Vercel（前端）+ Railway（后端）

请帮我：
1. 创建完整的项目目录结构
2. 配置开发环境（.env.example、.gitignore）
3. 搭建基础的 CI/CD 配置
4. 创建 Docker 开发环境配置

分步骤进行，每完成一步让我确认后再继续。
```

## 五、时间管理建议

```
学生可用时间假设：每天 2-3 小时

第 1 周：Idea 验证 + 需求定义 + 技术栈选择
第 2 周：前端核心页面 + Mock Data
第 3 周：后端 API + 数据库
第 4 周：前后端集成 + 部署上线

总计：约 4 周（每天 2-3 小时）
```
