# 原子设计方法论（Atomic Design）

> **适用场景**：组件库搭建、设计系统构建、前端架构规划
> **核心理念**：UI 是由小到大逐层组合的，先建原子再建分子
> **参考来源**：Brad Frost - Atomic Design

---

## 一、五级组件架构

```
┌─────────────────────────────────┐
│         Pages（页面）            │  ← 填充真实内容后的最终呈现
│  ┌───────────────────────────┐  │
│  │      Templates（模板）     │  │  ← 页面骨架，定义布局结构
│  │  ┌─────────────────────┐  │  │
│  │  │   Organisms（有机体） │  │  │  ← 独立功能区块
│  │  │  ┌───────────────┐  │  │  │
│  │  │  │ Molecules（分子）│  │  │  │  ← 原子的简单组合
│  │  │  │ ┌───────────┐ │  │  │  │
│  │  │  │ │Atoms（原子）│ │  │  │  │  ← 最小不可拆分的元素
│  │  │  │ └───────────┘ │  │  │  │
│  │  │  └───────────────┘  │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

## 二、各层级详解

### Atoms（原子）

> 最小不可拆分的 UI 元素，不能单独构成功能。

| 类别 | 示例 | 设计要点 |
|------|------|----------|
| 文字 | 标题、正文、标签、链接 | 定义字号阶梯和字重阶梯 |
| 图形 | 图标、Logo、分隔线 | 统一线条粗细和圆角 |
| 表单 | 输入框、复选框、单选框、开关 | 定义默认/聚焦/错误/禁用状态 |
| 按钮 | Primary / Secondary / Plain | 定义 3-5 个变体（见按钮层级体系） |
| 色块 | Badge、标签、色点 | 定义语义色和品牌色 |

**规则：** 每个 Atom 至少定义 3 个变体（默认、悬停/聚焦、禁用），关键 Atom 定义 5+ 变体。

### Molecules（分子）

> 原子的简单功能组合，具备单一明确的功能。

| 示例 | 组成原子 | 功能 |
|------|----------|------|
| 搜索栏 | 输入框 + 图标 + 按钮 | 搜索 |
| 列表项 | 头像 + 标题 + 描述 + 箭头 | 导航到详情 |
| 标签组 | 多个标签 Atom | 分类筛选 |
| 评分组件 | 多个星标图标 | 评分展示/输入 |
| Toast 通知 | 图标 + 文字 + 关闭按钮 | 操作反馈 |

**规则：** 分子内部的 Atom 间距使用统一的间距变量（space-2 / space-4），不硬编码。

### Organisms（有机体）

> 分子与原子的复杂组合，形成界面上可独立识别的功能区块。

| 示例 | 组成 | 功能 |
|------|------|------|
| 导航栏 | Logo + 菜单项 + 搜索栏 + 头像 | 全局导航 |
| 商品卡片 | 图片 + 标题 + 价格 + 按钮 | 商品展示 |
| 评论列表 | 多个"评论项"分子 | 内容展示 |
| 表单 | 多个"表单字段"分子 + 按钮 | 数据录入 |
| 设置面板 | 分组标题 + 开关 + 描述 | 配置管理 |

**规则：** Organism 是业务逻辑的最小承载单元，可独立测试和复用。

### Templates（模板）

> 页面的骨架结构，定义布局和内容区域，不包含具体内容。

| 示例 | 布局结构 |
|------|----------|
| 列表页模板 | 顶栏 + 搜索栏 + 筛选区 + 列表区 + 底栏 |
| 详情页模板 | 顶栏 + 头图 + 内容区 + 操作栏 |
| 设置页模板 | 顶栏 + 分组列表 |
| 弹窗模板 | 标题 + 内容区 + 按钮组 |

**规则：** 模板使用占位内容（灰色色块或 Lorem Ipsum），用于验证布局的合理性。

### Pages（页面）

> 填充真实内容后的最终呈现，用于最终验证。

**规则：** 页面是模板 + 真实数据 + 交互逻辑的集合，用于可用性测试和设计评审。

## 三、实践规则

### 规则 1：自下而上构建

```
开发顺序：Atoms → Molecules → Organisms → Templates → Pages
不要跳级！底层不稳定会导致上层频繁返工。
```

### 规则 2：组件变体管理

```
每个组件的变体通过 Props / Modifier 控制，不创建独立组件：

✅ 正确：<Button variant="primary" size="large" />
❌ 错误：<PrimaryButton /> <SecondaryButton /> <LargePrimaryButton />

变体维度：
- Variant（变体）：primary / secondary / tertiary / plain / destructive
- Size（尺寸）：small / medium / large
- State（状态）：default / hover / active / disabled / loading
- Icon（图标）：none / left / right / only
```

### 规则 3：组件文档规范

```
每个组件必须包含：
1. 组件名称和用途描述
2. 所有 Props/Variant 的说明
3. 默认状态和各状态的视觉表现
4. 使用示例（至少 3 个）
5. 不应使用的反模式示例
6. 无障碍（a11y）注意事项
```

### 规则 4：组件边界

```
何时拆分 vs 合并：
- 如果两个组件可以独立使用 → 拆分为独立组件
- 如果两个组件总是成对出现且位置固定 → 合并为一个组件
- 如果一个组件超过 200 行代码 → 考虑拆分
- 如果一个组件的 Props 超过 10 个 → 考虑拆分或使用 Slots
```
