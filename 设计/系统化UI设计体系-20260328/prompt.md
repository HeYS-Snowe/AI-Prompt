# 系统化 UI 设计体系（完整整合版）

> **适用场景**：移动端 / Web / 桌面端全平台 UI 设计与开发
> **核心理念**：设计必须成体系 —— 一致性、层级性、复用性、可扩展、约束性
> **设计风格**：现代、简洁、高级感（Apple / Google 风格向）

---

## 一、总纲：什么是"成体系"的设计

一个成体系的设计系统必须同时满足以下五个维度：

| 维度 | 定义 | 检验标准 |
|------|------|----------|
| **一致性** | 相同功能 → 相同样式 | 用户无需学习就能预知操作结果 |
| **层级性** | 通过视觉手段明确主次 | 一眼看出"先做什么、后做什么" |
| **复用性** | 组件可组合、不重复造轮子 | 新页面用现有规则组装即可 |
| **可扩展** | 规则能覆盖未来新增场景 | 不需要为每个新需求"发明"新样式 |
| **约束性** | 明确"能做什么、不能做什么" | 团队成员按同一套规则输出 |

## 二、苹果 HIG 按钮层级体系

### 2.1 核心原则

> 苹果的按钮哲学：**一个视图只突出一个动作**，用形状 + 颜色 + 填充三个维度共同表达层级。

### 2.2 五级按钮层级

| 层级 | 样式名称 | 形状 | 填充 | 典型场景 |
|------|----------|------|------|----------|
| **Primary** | Filled | 胶囊 / 药丸形 | 品牌色填充 | 页面上最重要的单一操作，每视图仅一个 |
| **Secondary** | Gray | 圆角矩形 | 浅灰填充 | 辅助操作，可多个并列 |
| **Tertiary** | Tinted | 圆角矩形 | 品牌色浅底 | 与主题色关联的辅助操作 |
| **Plain** | 纯文本 | 无形状 | 无 | 导航链接、行内操作 |
| **Destructive** | Red | 视上下文而定 | 红色填充/文字 | 删除、移除等不可逆操作 |

### 2.3 常见误区修正

- ❌ 错误认知："决策类按钮用胶囊，非决策类用圆角矩形"
- ✅ 正确理解："**Primary 级别的按钮用胶囊**，级别越低形状越弱化"
- 弹窗（Alert）中"确定"和"取消"都是胶囊形，因为弹窗场景下两者都是 Primary 级别，仅用颜色区分（蓝色 vs 灰色）

### 2.4 按钮设计规则

```
规则 1：一个视图（View/Screen）中，Primary 按钮 = 1 个
规则 2：Primary 按钮的位置应靠近其关联内容，或固定在页面底部
规则 3：Destructive 操作必须有二次确认，且不使用 Primary 样式
规则 4：按钮间距遵循 8pt 网格（见第五章）
规则 5：按钮最小可点击区域 = 44pt（iOS）/ 48dp（Android）
```

## 三、经典设计原则体系

### 3.1 苹果三大设计理念（HIG）

| 理念 | 含义 | 实践要求 |
|------|------|----------|
| **Clarity（清晰）** | 文字清晰、图标精确、装饰克制 | 每个元素的存在都有明确目的 |
| **Deference（服从）** | UI 退后，内容前置 | 用留白和层次让内容呼吸 |
| **Depth（层次）** | 通过层级和动效表达空间关系 | 阴影、模糊、过渡动效传递 Z 轴信息 |

### 3.2 Dieter Rams 十大设计原则（适配 UI）

1. **好的设计是创新的** —— 不抄袭，但可借鉴，结合新技术创造新交互
2. **好的设计是实用的** —— 形式追随功能，不为了好看而牺牲可用性
3. **好的设计是美观的** —— 功能与美学不矛盾，精心设计的界面让人愉悦
4. **好的设计是易懂的** —— 用户无需阅读说明书就能理解操作方式
5. **好的设计是克制的** —— 不抢戏、不干扰、不堆砌装饰
6. **好的设计是诚实的** —— 不用视觉手段欺骗用户（如假按钮、误导性颜色）
7. **好的设计是持久的** —— 避免追逐短期潮流，建立经得起时间考验的风格
8. **好的设计是细致的** —— 每个细节都经过考虑，不留随意之处
9. **好的设计是环保的** —— 在 UI 中体现为：减少认知负荷、节省用户注意力
10. **好的设计是尽可能少的设计** —— Less, but better

### 3.3 Material Design 3 核心理念（Google）

- **Dynamic Color（动态色彩）**：从用户壁纸提取主色调，实现个性化
- **Adaptive Layout（自适应布局）**：一套设计适配手机、平板、桌面
- **Design Token 体系**：颜色、圆角、阴影、间距全部参数化，通过变量统一管理
- **Motion System（动效系统）**：容器变换、共享轴、淡入淡出三大转场模式

## 四、原子设计方法论（Atomic Design）

### 4.1 五级组件架构

```
Pages（页面）
  └── Templates（模板）
        └── Organisms（有机体 / 复合组件）
              └── Molecules（分子 / 简单组合）
                    └── Atoms（原子 / 基础元素）
```

| 层级 | 定义 | 示例 |
|------|------|------|
| **Atoms（原子）** | 最小不可拆分的 UI 元素 | 按钮、输入框、图标、标签、色块 |
| **Molecules（分子）** | 原子的简单组合，具备单一功能 | 搜索栏（输入框 + 图标 + 按钮） |
| **Organisms（有机体）** | 分子与原子的复杂组合，形成独立功能区块 | 导航栏、卡片列表、评论区、表单 |
| **Templates（模板）** | 页面骨架，定义布局和内容区域 | 页面框架（顶栏 + 内容区 + 底栏） |
| **Pages（页面）** | 填充真实内容后的最终呈现 | 首页、设置页、个人中心 |

### 4.2 实践规则

```
规则 1：先设计 Atoms，再逐层向上组合，确保底层稳定
规则 2：每个 Atom 定义 3-5 个变体（如按钮：Primary / Secondary / Tertiary / Plain / Destructive）
规则 3：Molecule 内的 Atom 间距用统一变量，不硬编码
规则 4：Organism 是业务逻辑的最小承载单元
规则 5：Template 只定义布局结构，不包含具体内容
```

## 五、8pt 网格与间距体系

### 5.1 基础规则

```
基础单位 = 4px
常用单位 = 8px（基础单位的 2 倍）

所有间距、圆角、内边距、外边距、元素尺寸必须是 4 的倍数。
优先使用 8 的倍数，4px 仅用于精细调整。
```

### 5.2 间距标尺

| Token 名称 | 值 | 用途 |
|------------|-----|------|
| `space-1` | 4px | 图标与文字的最小间距、紧凑列表项间距 |
| `space-2` | 8px | 相关元素组内间距、输入框内边距 |
| `space-3` | 12px | 标签与内容的间距 |
| `space-4` | 16px | 卡片内边距、列表项间距 |
| `space-5` | 20px | 段落间距 |
| `space-6` | 24px | 区块之间的间距 |
| `space-8` | 32px | 卡片之间的间距、大区块分隔 |
| `space-10` | 40px | 页面内容与边缘的安全距离 |
| `space-12` | 48px | 页面级大间距 |
| `space-16` | 64px | 章节/模块之间的分隔 |

### 5.3 圆角标尺

| Token 名称 | 值 | 用途 |
|------------|-----|------|
| `radius-sm` | 4px | 小标签、Badge |
| `radius-md` | 8px | 输入框、小卡片 |
| `radius-lg` | 12px | 卡片、弹窗 |
| `radius-xl` | 16px | 底部弹窗、大面板 |
| `radius-full` | 9999px | 胶囊按钮、头像、药丸标签 |

## 六、色彩层级体系

### 6.1 四层色彩架构

| 层级 | 用途 | 说明 |
|------|------|------|
| **Brand Color（品牌色）** | Primary 按钮、强调元素、Logo | 通常 1 个主色 + 1 个辅色 |
| **Neutral Palette（中性色系）** | 背景、文字、边框、分隔线 | 10 级灰阶，从白到黑平滑过渡 |
| **Semantic Color（语义色）** | 成功 / 警告 / 错误 / 信息 | 固定含义，全局一致 |
| **Surface Color（表面色）** | 卡片、弹窗、面板的层级区分 | 用不同深浅表达 Z 轴层次 |

### 6.2 中性色系（10 级灰阶参考）

```
neutral-0   #FFFFFF  —— 纯白，主背景
neutral-1   #F7F8FA  —— 次级背景、卡片背景
neutral-2   #EEF0F4  —— 输入框背景、分割线
neutral-3   #E2E5EB  —— 禁用状态背景
neutral-4   #CDD1D9  —— 占位符文字、次要边框
neutral-5   #9BA1AD  —— 次要文字、图标
neutral-6   #6B7280  —— 正文文字
neutral-7   #4B5563  —— 标题文字
neutral-8   #374151  —— 重要标题
neutral-9   #111827  —— 最高层级文字、纯黑替代
```

### 6.3 语义色（固定含义）

| 语义 | 色值参考 | 用途 |
|------|----------|------|
| Success | #10B981 / Green-500 | 操作成功、已完成、在线状态 |
| Warning | #F59E0B / Amber-500 | 需注意、即将过期、低电量 |
| Error   | #EF4444 / Red-500    | 错误、失败、不可用 |
| Info    | #3B82F6 / Blue-500   | 提示信息、帮助、链接 |

### 6.4 表面色层级（Z 轴层次表达）

```
Surface 0（最低） → 页面主背景
Surface 1        → 卡片、列表容器
Surface 2        → 弹窗、抽屉、浮层
Surface 3        → Toast、Tooltip、下拉菜单
Surface 4（最高） → Modal 遮罩层

规则：层级越高，颜色越浅（亮色模式）或越深（暗色模式），
      可配合阴影加强层次感。
```

### 7.1 字号阶梯

| Token | 值 | 用途 |
|-------|-----|------|
| `text-xs` | 12px | 辅助说明、Badge、时间戳 |
| `text-sm` | 14px | 次要文字、列表描述 |
| `text-base` | 16px | 正文（移动端基准） |
| `text-lg` | 18px | 小标题、强调文字 |
| `text-xl` | 20px | 二级标题 |
| `text-2xl` | 24px | 一级标题 |
| `text-3xl` | 30px | 页面大标题 |
| `text-4xl` | 36px | 营销页 Hero 标题 |

### 7.2 字重阶梯

| Token | 值 | 用途 |
|-------|-----|------|
| `font-normal` | 400 | 正文 |

### 7.3 行高规则

```
正文行高 = 字号 × 1.5
标题行高 = 字号 × 1.3
紧凑行高 = 字号 × 1.2（仅用于表格、标签）
```

## 八、暗色模式适配规则

### 8.1 核心原则

```
规则 1：不要简单反转黑白，而要重新设计每个色阶
规则 2：暗色模式下降低纯白的使用（#000000 → #0A0A0A），避免刺眼
规则 3：品牌色在暗色模式下适当提亮（+10%~20% 饱和度）
规则 4：阴影在暗色模式下减弱，用边框替代
规则 5：图片和插画在暗色模式下适当降低亮度（-5%~-10%）
```

### 8.2 表面色反转规则

| 层级 | 亮色模式 | 暗色模式 |
|------|----------|----------|
| Surface 0 | #FFFFFF | #0A0A0A |
| Surface 1 | #F7F8FA | #161616 |
| Surface 2 | #EEF0F4 | #1F1F1F |
| Surface 3 | #FFFFFF + Shadow | #2A2A2A + Border |
| Surface 4 | Black 50% opacity | Black 70% opacity |

## 九、动效设计原则

### 9.1 动效的三个用途

1. **反馈** —— 用户操作后的即时响应（点击、滑动、切换）
2. **引导** —— 吸引用户注意力到新内容或变化
3. **连接** —— 表达元素之间的空间关系和因果关系

### 9.2 时长规则

| 场景 | 时长 | 缓动曲线 |
|------|------|----------|
| 微交互（按钮按压、开关切换） | 100-200ms | ease-out |
| 状态变化（展开/收起、Tab 切换） | 200-300ms | ease-in-out |
| 页面转场 | 300-500ms | ease-in-out |
| 复杂动画（列表重排、布局变化） | 300-600ms | spring / cubic-bezier |

### 9.3 通用规则

```
规则 1：动画必须有目的，装饰性动画 < 1s 后停止
规则 2：遵循用户"减少动态效果"的系统设置
规则 3：进入动画 > 退出动画（进入时慢一点更有仪式感）
规则 4：列表动画使用 stagger 延迟（每项延迟 30-50ms）
```

## 十、使用指南

将本提示词作为 UI 设计和开发的**全局规范**，在以下场景中引用：

1. **设计新页面时** —— 先确定层级、再选组件、最后调间距
2. **Code Review 时** —— 检查是否违反间距标尺、色彩层级、按钮层级
3. **建立组件库时** —— 按原子设计五级架构组织
4. **设计评审时** —— 以"一致性"和"层级性"为首要评判标准
