# oklch 色彩系统：感知均匀的配色策略

**适用场景**：Web/App UI 配色、设计系统色彩定义、AI 生成配色的修正与约束
**核心原则**：用感知均匀的 oklch 色彩空间派生和谐配色，规避 HSL 的感知不均匀陷阱

## 一、核心策略（Claude Design Skill 原文）

> Color usage: try to use colors from brand / design system, if you have one. If it's too restrictive, use oklch to define harmonious colors that match the existing palette. **Avoid inventing new colors from scratch.**

配色落地优先级：

1. **优先复用**品牌 / 设计系统已有色彩
2. 不够用时，用 **oklch 色彩空间**派生和谐的衍生色
3. **禁止**凭空发明新颜色（inventing from scratch）

## 二、为什么是 oklch（对比 HSL）

| 维度 | HSL | oklch |
|------|-----|-------|
| 感知均匀性 | ❌ 感知不均匀 | ✅ 感知均匀 |
| 同亮度视觉效果 | 同样的亮度值，**黄色看起来比蓝色亮得多** | 相同的亮度值 = 人眼感受到的**相同亮度** |
| AI 随机配色结果 | 经常看起来不和谐 | 固定 L、C 改 h，**自动和谐** |

**关键结论**：HSL 感知不均匀，导致 AI 用 HSL 随机生成的配色经常看起来不和谐；oklch 是感知均匀的色彩空间，相同 L 值代表人眼相同的亮度感受，因此能稳定产出和谐配色。

## 三、oklch 三分量

```
oklch(L C h)
      │ │ │
      │ │ └─ h = 色相角（hue），单位：度（0~360）
      │ └─── C = 色度（chroma），饱和度（0~约0.37）
      └───── L = 亮度（lightness），0~1
```

**和谐配色公式**：保持 **L（亮度）和 C（色度）不变，只改变 h（色相角）** → 自动得到一组感知和谐的色彩搭配。

> 这是 oklch 配色的核心心法：锁亮度、锁彩度、转色相。

## 四、配色预设示例

从原文抓取到的已确认值：

| 预设名 | oklch 值 | 分量解读 |
|--------|---------|----------|
| 近黑 / 深色 | `oklch(0.10 0.015 250)` | L=0.10 低亮度 · C=0.015 低彩度 · h=250 蓝色相 |
| 暖棕 / 暖亮色 | `oklch(0.78 0.13 65)` | L=0.78 高亮度 · C=0.13 中彩度 · h=65 暖黄橙 |

| 调性 | 配色预设 | 字体配对 | 适用行业 |
|------|----------|----------|----------|
| 高端中性 | （暖棕 / 近黑系） | — | 奢侈品、咨询 |

## 五、避坑：AI 配色常见坏习惯

- ❌ 用**高饱和度发光阴影**（glow / neon shadow）勾勒边框和文字 —— AI 最常用的偷懒手段，廉价感强
- ❌ **凭空发明**新颜色（不从现有 palette 派生）
- ❌ 用 **HSL 随机生成**配色 —— 感知不均匀导致不和谐

## 六、即用 Prompt

```
为以下界面定义色彩系统，使用 oklch 色彩空间：

约束：
1. 保持亮度和色度不变，仅调整色相角派生和谐色板
2. 优先匹配现有品牌色，不够时用 oklch 派生，禁止凭空发明新颜色
3. 禁止高饱和度发光阴影勾勒边框/文字

输出：
- 主色 / 辅色 / 中性色 / 语义色（成功·警告·错误·信息）
- 每个颜色给出 oklch() 值 + 16 进制 fallback
- 说明各色的 L、C、h 取值依据
```

## 关键要点

1. **oklch 感知均匀，HSL 不是** —— 这是用 oklch 的根本理由
2. **和谐配色 = 固定 L、C，变 h** —— 一句话心法
3. **配色优先级**：品牌色 > oklch 派生 > 凭空发明（禁止）
4. **避开廉价感**：不用高饱和度发光阴影
