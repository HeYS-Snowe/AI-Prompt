# 网页转 DESIGN.md — 网站设计系统提取提示词

> 来源：web-to-design-md（Paidax01/web-to-design-md）skill 提炼，2026-08-04 沉淀

## 适用场景

- 给定一个或多个网站 URL，要求分析网站、逆向设计、提取 look and feel
- 需要把某网站的视觉语言、布局系统、交互模式、内容风格提炼为结构化 DESIGN.md 文档
- 目标是**产出可复用的设计系统文档**（供另一 AI 代理据此重建同款设计），而非克隆页面
- 与「DESIGN.md设计系统格式规范-20260405」搭配使用：前者是格式规范，本提示词是提取工作流

## 核心原则

1. **浏览器优先、证据优先**：用 `agent-browser`（open/wait/eval）为主提取手段；不优先用原始 HTML 抓取，不用截图当默认证据
2. **agent-browser 缺失时**：先帮用户安装/暴露到 PATH，不静默切换到 Playwright/Chrome CLI/截图方案
3. **技术细节转设计语言**：不盲目倾倒 CSS，综合成可用的设计规则；区分**观察到的事实**与**推断**
4. **交付物**：默认产出 `DESIGN.md` + 同名 `-preview.html` 预览（除非用户另有要求）

## 工作流

### 1. Preflight

- 规范化目标为 1 个或多个 URL
- 检查 agent-browser 可用性（缺失则先安装）
- 默认输出文件 `DESIGN.md`，预览文件 `DESIGN-preview.html`（用户指定则遵从其命名）
- 多 URL：分别检查，仅当视觉语言跨页一致时才综合为一套设计系统

### 2. 提取（六道工序）

1. **页面范围**：页面用途、类型（营销/产品/仪表盘/文档/电商/编辑/混合）、自上而下的重要区块、受限区域（标注而非虚构）
2. **基线采集**：桌面优先，布局实质变化时补平板/手机；慢滚全页（勿漏延迟动画、sticky、渐进披露）；采集渲染 HTML、关键节点 outerHTML、根 CSS 变量、可读样式规则、代表组件计算样式
3. **设计系统**：颜色及角色、明暗主题变体、排版层级、间距节奏与栅格、圆角语言、边框处理、阴影与表面分层、图片/图标风格、动效风格、密度与留白哲学、样式表约定、DOM 重复组件结构
4. **组件与状态**：导航/公告栏/hero/按钮链接/卡片/徽章/表单输入/tab/手风琴/表格/页脚；每个组件检查 default/hover/active/focused/disabled/scroll-sticky/open/明暗变体
5. **交互行为**：滚动变化、hover 变化、点击变化、明暗切换变化、入场动画、轮播/tab/sticky 是点击驱动/滚动驱动/时间驱动、动效速度与质感、可观察的 CSS/DOM 状态变化
6. **内容与品牌语气**：标题风格、CTA 措辞、句子密度、产品框架、信任信号、功能命名模式、文案是技术/俏皮/高端/直接/学术/对话式

### 3. 主题模式扫描（站点支持切换时）

- 直接在浏览器中触发明暗切换
- 提取两种模式的 DOM 与计算样式证据
- 记录哪些 token 反转、哪些强调色稳定
- 图片/阴影/边框/卡片/代码块的模式差异
- 两种模式都写入最终 md 与预览

### 4. 输出（九段式结构）

1. `Visual Theme & Atmosphere` — 视觉主题与氛围（至少一段密集描述）
2. `Color Palette & Roles` — 色彩与角色（多组色群，精确 hex，绑定功能）
3. `Typography Rules` — 排版规则（完整层级表：字号/字重/行高/字距）
4. `Component Stylings` — 组件样式（按钮/卡片容器/输入表单/导航/图片处理/特色组件，含状态细节）
5. `Layout Principles` — 布局原则（间距系统/栅格与容器/留白哲学/圆角尺度）
6. `Depth & Elevation` — 深度与层级（阴影公式/表面分层）
7. `Do's and Don'ts` — 该做与不该做
8. `Responsive Behavior` — 响应式行为（断点/触控目标/折叠策略）
9. `Agent Prompt Guide` — 代理提示指南（快速色板参考/示例组件提示词/迭代规则）

可选附录：`Interaction Patterns`、`Content & Messaging Patterns`、`Observed Pages`、`Evidence Notes`。

### 5. HTML 预览

- 用固定预览壳模板（design-preview-shell.template.html），不每次新造框架
- 左侧展示最实用视觉规则（概览/色板/排版/间距/圆角/按钮/卡片/深度/响应式）
- 保留 markdown 原文面板；用提取的设计 token 渲染，使预览本身反映文档体系

## 质量门槛（完成前自检）

- 另一代理仅凭本文档能否复现站点氛围？
- 主色是否绑定具体功能？排版层级是否可直接复用？
- 主要组件状态细节是否足够？影响构图的响应式变化是否记录？
- 文案语气是否被捕捉（不止 UI 外壳）？
- 是否避免虚构隐藏页面/不可见状态？
- 是否知道间距/圆角/阴影尺度以重建组件库？
- 是否至少含 2-4 个签名区块的 prompt-ready 示例？

任一为否 → 重新检查站点后再定稿。
