# 经典设计原则体系

> **适用场景**：所有 UI/UX 设计与开发的指导思想
> **核心理念**：Less, but better —— 好的设计是不被注意的设计
> **参考来源**：Apple HIG、Dieter Rams、Material Design 3

---

## 一、苹果三大设计理念

### 1. Clarity（清晰）

> 每个元素的存在都有明确目的，用户无需猜测。

**实践清单：**
- 文字表达准确，不使用技术术语面向普通用户
- 图标含义明确，无歧义（如用放大镜表示搜索，而非用雷达）
- 装饰性元素最小化，不干扰信息传达
- 字号层级不超过 4 级，颜色层级不超过 3 级

### 2. Deference（服从内容）

> UI 退后，内容前置。界面的存在是为了让内容发光。

**实践清单：**
- 导航栏和工具栏使用半透明模糊（Frosted Glass），不遮挡内容
- 留白是设计的一部分，不是"浪费空间"
- 默认隐藏高级选项，减少首屏认知负荷
- 媒体内容（图片/视频）优先使用全宽展示

### 3. Depth（层次感）

> 通过视觉层次传递空间关系，让用户理解界面结构。

**实践清单：**
- 用阴影和模糊区分前景与背景
- 用颜色深浅表达 Z 轴层级（Surface Color 体系）
- 用动效（转场、缩放）表达元素间的空间关系
- 弹窗/抽屉出现时，背景内容适当暗化

## 二、Dieter Rams 十大设计原则（UI 适配版）

| # | 原则 | UI 中的实践 |
|---|------|------------|
| 1 | **好的设计是创新的** | 结合手势、动画、AI 等新技术创造新交互方式，而非模仿旧范式 |
| 2 | **好的设计是实用的** | 每个元素都必须有明确功能，不为"好看"而牺牲可用性 |
| 3 | **好的设计是美观的** | 精心选择字体、颜色、间距，让功能本身就令人愉悦 |
| 4 | **好的设计是易懂的** | 用户无需阅读说明就能理解操作方式，自解释的界面 |
| 5 | **好的设计是克制的** | UI 元素退居幕后，让用户专注于自己的任务 |
| 6 | **好的设计是诚实的** | 不用视觉手段欺骗用户（假按钮、误导性颜色、暗黑模式） |
| 7 | **好的设计是持久的** | 避免追逐短期视觉潮流，建立经得起时间考验的风格系统 |
| 8 | **好的设计是细致的** | 每个像素都经过考虑，不留随意之处 |
| 9 | **好的设计是环保的** | 减少认知负荷、节省用户注意力，不信息轰炸 |
| 10 | **好的设计是尽可能少的设计** | Less, but better —— 删掉一切可以删的 |

## 三、Material Design 3 核心理念

### 3.1 Dynamic Color（动态色彩）

```
核心思想：从用户壁纸/主题中提取主色调，动态应用到整个应用。
实现方式：
- 定义 1 个 Source Color（种子色）
- 由系统自动生成完整的 Color Scheme（色调映射）
- 包含 Primary / Secondary / Tertiary / Surface / Error 等完整色阶
```

### 3.2 Design Token 体系

```
所有视觉属性通过 Token 管理，而非硬编码：

语义 Token（业务层）：
  --color-primary       → 品牌色
  --color-on-primary    → 品牌色上的文字色
  --color-surface       → 卡片背景色
  --color-on-surface    → 卡片上的文字色

基础 Token（系统层）：
  --md-sys-color-primary      → #6750A4
  --md-sys-color-on-primary   → #FFFFFF

规则：组件引用语义 Token，不直接引用基础 Token。
      这样更换主题时只需修改基础 Token 的映射。
```

### 3.3 Motion System（动效系统）

| 转场模式 | 适用场景 | 运动方向 |
|----------|----------|----------|
| **Container Transform** | 列表项展开为详情页 | 容器从 A 位置变形到 B 位置 |
| **Shared Axis** | 同层级页面切换 | X 轴（左右滑动）或 Z 轴（前进/后退） |
| **Fade Through** | 内容完全不同的页面切换 | 旧内容淡出 → 新内容淡入 |
| **Fade** | 元素的出现/消失 | 透明度渐变 |

## 四、尼尔森十大可用性原则（Heuristic Evaluation）

| # | 原则 | 简述 |
|---|------|------|
| 1 | **状态可见性** | 系统状态应始终让用户感知到（加载指示器、进度条） |
| 2 | **系统与现实匹配** | 使用用户熟悉的语言，而非技术术语 |
| 3 | **用户控制与自由** | 提供"撤销"和"重做"，支持明确的"退出"方式 |
| 4 | **一致性与标准** | 相同功能使用相同样式和交互方式 |
| 5 | **错误预防** | 好的设计比好的错误提示更重要（如确认弹窗） |
| 6 | **识别优于回忆** | 让用户看到选项，而非要求他们回忆 |
| 7 | **灵活性与效率** | 为新手提供引导，为专家提供快捷方式 |
| 8 | **美学与极简** | 对话中不应包含无关信息，每个额外信息都会降低主要信息的可见度 |
| 9 | **帮助用户识别和恢复错误** | 用清晰的语言指出错误，并提供解决方案 |
| 10 | **帮助与文档** | 即使不需要文档就能使用，也应提供可检索的帮助信息 |

## 五、Fitts's Law（菲茨定律）在 UI 中的应用

```
定律公式：T = a + b × log₂(D / W + 1)
T = 到达目标的时间
D = 起点到目标的距离
W = 目标的宽度

UI 实践推论：
1. 按钮越大越容易点击（W ↑ → T ↓）
2. 按钮越靠近手指当前位置越容易点击（D ↓ → T ↓）
3. 屏幕边缘和角落是"无限大"的目标（容易到达）
4. 将常用操作放在拇指热区（移动端底部 1/3）
5. 危险操作远离拇指热区，减少误触
```
